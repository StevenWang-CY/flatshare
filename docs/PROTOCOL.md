# Protocol

What the gateway, `flatshare-gateway`, accepts from callers and sends to the engines, for a reader who writes a client
of the gateway or reads its code. The wire types are defined once, in [`crates/flatshare-proto`](../crates/flatshare-proto),
which generates the Python components' [JSON Schemas](../crates/flatshare-proto/schema/). After changing a type,
regenerate them, or a test fails:

```sh
make schema    # cargo run -p flatshare-proto --bin flatshare-proto-schema
```

## Sessions

A session is one conversation, scoped to a tenant. It is the key by which the gateway places a request on a GPU node,
follows a call's turns and names the request to the engine. The gateway resolves it from the first of these that is
present:

1. `X-Session-ID`, from a trusted tenant only (the voice worker sends `voice-<room SID>`, one per LiveKit room);
2. `X-Claude-Code-Session-ID`;
3. the OpenAI `prompt_cache_key`;
4. otherwise a minted id, `m-` and 32 random hex digits.

Session ids are 1–128 characters from `[A-Za-z0-9._:-]`, safe in headers, and a trusted tenant's id of that form is
used as it is. Any other source, and any source from an untrusted tenant, is hashed into a tenant-scoped id, `h-` and
the first 32 hex digits of SHA-256(tenant, NUL, source), so that no tenant can name another's session. Every proxied
inference response returns the resolved id in `X-Flatshare-Session-ID`.

## Headers

| Header | Direction | Meaning |
|---|---|---|
| `X-Session-ID` | trusted caller → gateway → engine | The session id, which vLLM records in its GPU-tier KV events (the frozen box publishes none) |
| `X-Claude-Code-Session-ID` | caller → gateway | Claude Code's own session header |
| `X-Flatshare-Class` | trusted caller → gateway | The class: `realtime`, `interactive` or `background`; from any other caller, the tenant's default class |
| `X-Flatshare-Session-ID` | gateway → caller | The session id the gateway resolved or minted |
| `X-Flatshare-Canary` | gateway → engine | `1` on the gateway's own canary requests, to name them in the engine's logs |
| `X-Vllm-Priority` | gateway → engine | vLLM's priority, from the class: realtime 0, interactive 1, background 2 (lower runs first). Sent when `upstream_priority` lists `vllm-header`, the default |
| `X-SMG-Priority` | gateway → router | SMG's class: realtime `system`, interactive `interactive`, background `bulk`. Sent when `upstream_priority` lists `smg-header` (E2 arm 8b) |
| `X-Request-Id` | gateway → engine, caller | One id per request, generated by the gateway; vLLM uses it as its request id |

No `X-Flatshare-` header that a caller sends reaches the engine.

**Inputs the gateway owns.** The engines trust some inputs for scheduling, caching and accounting, so the gateway
strips them from every client request and sets its own:

| Kind | Names |
|---|---|
| Headers | `X-Vllm-Priority`, `X-SMG-Priority`, `X-Session-ID` (from untrusted callers), `X-data-parallel-rank`, `X-Request-Id` |
| Body fields | vLLM's `session_id`, `priority`, `kv_transfer_params`, `ec_transfer_params`, `cache_salt`, `request_id`, `vllm_xargs`; SGLang's `rid`, `extra_key`, `session_params`, `custom_labels`, `routed_dp_rank`, `data_parallel_rank`, `disagg_prefill_dp_rank`, `bootstrap_host`, `bootstrap_port`, `bootstrap_room` |

When `upstream_priority` lists `body`, the gateway writes the class's engine priority into the body's `priority`, which
SGLang reads (E2 arm 7b). vLLM takes `X-Vllm-Priority` over the body's, and its FCFS scheduler ignores both.

Each tenant's `cache_salt` is the first 32 hex digits of HMAC-SHA-256 of the tenant's name, keyed by the 32 random
bytes of `cache_salt_secret_file`, so rotating a key keeps the tenant's cache and the name alone does not give it away.

## Lifecycle events

The voice worker tells the gateway where each call is. In bench mode it sends every voice event below, for E2's
lifecycle policy, and in serve mode `session_closed` alone, which ends the session's placement under `[[nodes]]`.

- **Delivery.** Trusted callers `POST` events to `/v1/events`, as one JSON object or an array, and get 202
  `{"accepted": n, "duplicates": m}`. The voice worker posts over the gateway's Unix socket, keyless, with a 1 s
  timeout and no retry, since a late timing signal would mislead.
- **Idempotency.** Events are idempotent by `(tenant, source, event_id)` within a window, by default 100,000 ids for 10
  minutes, and a repeat is acknowledged and ignored.
- **Unknowns.** Unknown fields are ignored, and an unknown `type` is rejected with 400, with the whole batch that
  contains it.

```json
{"event_id": "voice-RM_a1B2c3-4", "session_id": "voice-RM_a1B2c3", "at_ms": 1792650014940,
 "source": "voice-worker", "type": "interrupted", "played_ms": 1840}
```

| Field | Meaning |
|---|---|
| `event_id` | Idempotency key, unique per emitter; the voice worker's is the session id, a nonce and a sequence number |
| `session_id` | The session: for a call, the requests' `X-Session-ID` (`voice-<room SID>`) |
| `at_ms` | When the emitter observed the event, on its clock, in Unix epoch ms; ordering uses the gateway's receipt time |
| `source` | `voice-worker`, `agentic-api` or `client` |
| `type` | The event type, below |

Under the lifecycle policy the gateway keeps each realtime session's turn state from the voice events
([ARCHITECTURE.md §7](ARCHITECTURE.md#7-designs-measured-and-dropped)). Every state but idle times out after
`state_timeout_s` without an event, and a realtime request opens its session's critical window too. Under any other
policy the events are counted and change no decision.

| `type` | Extra fields | The voice worker sends it | Under the lifecycle policy |
|---|---|---|---|
| `user_speech_started` | — | at VAD onset | Arms the session's KV headroom (with `trigger = "onset"`) |
| `user_turn_ended` | — | at the end-of-turn decision | Opens the critical window, in which background prefill is budgeted |
| `playback_started` | — | at the reply's first audio | Closes the critical window |
| `playback_ended` | `played_ms` | at the reply's end | Back to idle |
| `interrupted` | `played_ms`, what the caller heard | on barge-in | The caller is speaking again |
| `session_closed` | — | when the caller hangs up | Forgets the session |
| `turn_started`, `turn_finished`, `tool_wait_started`, `tool_wait_ended` | `stop_reason` and token counts; `tool`, `eta_ms` | never: an agent framework's sink is proposed in [agentic-api#364](https://github.com/vllm-project/agentic-api/issues/364) | Accepted, no effect: in E1 even exact tool-return times closed under 8% of resume TTFT at p50 ([ADR-0006](adr/0006-the-engine-change-carries-the-realtime-tier.md)) |

[`flatshare-voice`](../python/flatshare_voice/README.md#lifecycle-events-and-turn-lines) gives the LiveKit hook behind
each voice event and when it fires.

## Placement

With `[[nodes]]`, `POST /v1/sessions` from a trusted tenant places a session on a GPU node before its first request
and answers with the node and its speech servers. When no node can take it, the answer is 503 with `Retry-After: 1`
(`no_healthy_node`, `no_call_slot`, `no_agent_slot` or `placement_full`). `DELETE /v1/sessions/{id}` from its tenant
frees the slot at once, as a `session_closed` event does, and answers 200 either way. The voice worker ends each call it
placed so ([the gateway's Nodes](../crates/flatshare-gateway/README.md#nodes)). Without `[[nodes]]` a gateway has one
upstream and places nothing.
